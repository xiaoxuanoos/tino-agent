# Tino Agent 公网部署边界

本地桌面应用与网页后台使用独立的 `.tino-runtime`。现有网页后台的
`HERMES_HOME`、对话、工具、终端、文件和模型凭据属于同一个运行主体；
它**不是**多租户服务。单个密码保护页面并不会让公开注册的用户彼此隔离。

## 上线前必须具备

1. 与既有项目分开的云实例或经过明确资源配额规划的专属主机；独立域名、
   TLS 证书、独立存储卷和备份。不可沿用旧项目的服务端口、数据库、
   环境变量、API 密钥或系统账号。
2. 控制平面：邮箱验证、带限速的注册/登录、密码哈希与重置、会话撤销、
   CSRF 防护、审计和滥用配额。模型 API 密钥只加密存储在所属租户范围。
3. 数据平面：每位用户单独的进程/容器、操作系统身份、只属于自己的
   `HERMES_HOME` 和密钥，限制文件系统、网络、CPU、内存、磁盘与工具权限；
   前置网关只把已认证请求送入该用户的运行环境。禁止把 Docker socket
   或其他租户的挂载卷交给 Agent 终端。
4. 端到端隔离测试：两个账号分别登录，分别保存模型密钥和聊天，然后
   交叉访问会话、文件、终端、API、WebSocket，均应被拒绝；再执行
   备份恢复、密码重置、退出登录和并发限流测试。

在这些条件通过前，只允许环回地址上的单用户本地调试，不开放 DNS
流量或公众注册。微信、QQ、Google、短信验证需要各平台的已审核应用
与凭据，不能用一个静态登录页冒充其身份验证。

## 2026-09-22 香港资源只读核查

- 香港区域仅有一台轻量应用服务器，2 vCPU / 2 GiB 标称内存、40 GiB 磁盘；
  系统报告可见内存约 1.6 GiB，未配置 swap。当前未发现监听中的网络服务。
- 这台实例绑定的密钥对名称指向既有项目，因此不能推断它可供 Tino 专用；
  香港 ECS 列表没有另一台实例。核查只执行了系统、内存、磁盘和端口的
  只读命令，没有安装软件、开放端口、改 DNS 或动旧项目。
- 即使只使用云端模型 API，这个规格也不适合作为带终端/浏览器权限、公开
  注册的多租户 Agent 主机。独立实例和数据平面隔离是公网部署的前置条件。
- 用户提出“不在本机运行”后，本机 Tino 配置已关闭本地模型服务自动启动，
  默认改用已验证的云端模型；已下载模型文件保留，未删除用户数据。

下一步在**专供 Tino 的香港实例**上完成隔离部署：建议从至少 4 vCPU /
8 GiB 的容量规划开始，并以云模型 API 作为默认推理；这个数字只是初始
容量建议，必须以并发压测再定。先实现控制平面和按用户隔离的运行环境，
通过双账号交叉访问测试，再配置独立域名、TLS 和公开入口。在此之前不能把
现有单用户 dashboard 当作已完成的公众服务。

下一阶段应先确认独立实例及域名，再实现和审计上述多租户边界，最后
部署灰度环境并执行跨租户攻击测试。不要直接把当前 dashboard 公开在互联网。
